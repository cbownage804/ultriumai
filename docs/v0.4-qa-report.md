# v0.4 QA & Hardening — Report

Scope: Recommendations Engine, Organization Memory, Conversational Ray,
Weekly Digest, plus performance/security/UX/tests. No new features added.

## Defects fixed

| # | Severity | Area | Defect | Fix |
|---|----------|------|--------|-----|
| 1 | **High** | Org Memory RLS | `ray_org_memory_admin_insert` policy had `WITH CHECK = NULL`, so any authenticated user could insert facts for an arbitrary `org_id` (cross-org data injection). | New policy re-scopes INSERT to owner/admin/org_admin of the target org. |
| 2 | Medium | Recommendations | Auto-resolved findings had no lifecycle — findings that were no longer detected stayed "new" forever, cluttering the list. | `ray-scan` now marks any open, fingerprinted rec that was not re-detected this run as `resolved` (`auto_resolved` counter returned in payload). |
| 3 | Medium | Recommendations | Reopening a resolved-danger finding did not clear `completed_at` / `dismissed_at`, leaving misleading timestamps. | Reopen path clears both timestamps. |
| 4 | Medium | Digest | Existing-row lookup in `ray-digest-build` scoped only the non-null field (`org_id` OR `user_id`). Two scopes sharing a week could match each other. | Query now `.eq(...).is(other, null)` so scope isolation is enforced regardless of the unique index. |
| 5 | Low | Recommendations UI | Findings were sorted alphabetically by `severity` (`danger`, `info`, `success`, `warn`) — `info` beat `warn`. | Sort by `priority` column (1=danger, 2=warn, 3=info). |
| 6 | Low | Recommendations UI | Scan toast didn't surface the new `auto_resolved` count. | Toast now includes it when > 0. |

## Verified behaviors (no code change needed)

### Recommendations
- **Determinism** — `fingerprintOf(user, org, category, rule, subject)` is content-derived SHA-1; identical inputs → identical fingerprint. Unit tested (`scan.test.ts`).
- **Deduplication** — `ray_recommendations_fingerprint_uniq` partial unique index enforces one row per fingerprint. `ray-scan` updates by fingerprint instead of inserting.
- **Dismissed persistence** — reopen path only fires when previous status was `resolved` AND detected severity is `danger`. `dismissed` stays dismissed. Verified in code + covered by fixture design.
- **Priority ordering** — `priority` column derived at scan time from severity (1/2/3), used by list query.
- **No-data orgs** — `scanDevices` returns `[]` when no devices; `scanIdentity` guards each source. Empty state renders "You're all clear!" card on `/app/ray/recommendations`.

### Organization Memory
- **RLS** — SELECT / UPDATE / DELETE / INSERT policies all now require `has_role owner|admin|org_admin` on the exact `org_id`. Cross-org queries return 0 rows.
- **Uniqueness** — `ray_org_memory_org_id_key_key` unique index prevents contradictory memories on the same key within an org; upsert flow updates in place.
- **Ray injection** — Knowledge skill in `ray-router/_lib.ts` fetches memory via `fetchOrgMemory(orgId)` and prepends as "authoritative context" only when the caller belongs to an org.

### Conversational Ray
- **Cross-user isolation** — chat history is not persisted client-side across sessions; router only sees the current message + optional context object. `ray_skill_invocations` is scoped by `user_id` in RLS.
- **Action-button gating** — Only `navigate` and `external` intents render as clickable in `RaySkillsPanel`; other intents surface a toast instead of executing. Actions come from skill output, which limits to real navigate targets.
- **Context follow-ups** — `ray-router` prepends `[Context: kind] Title/Details` header before the user question so classifier + skill both see it.
- **Audit** — every invocation (success or failure) writes to `ray_skill_invocations` with source, latency, classifier confidence, error.

### Weekly Digest
- **Duplicate prevention** — unique index on `(coalesce(org_id, 0), coalesce(user_id, 0), week_start)` + (now correctly scoped) existing-row lookup means one build per (scope, week).
- **Timezone** — `weekBounds()` operates entirely in UTC on `Date.setUTCHours/setUTCDate`; produces stable Mon-Sun window for the *previously completed* week. Unit tested (`digest.test.ts`).
- **Recipient scoping** — org digests only email owners/admins (via `org_team_members.role IN ('owner','admin')`); user-scope digests email only that user.
- **Zero-activity orgs** — digest renders "No new findings this week. Nice." for empty highlights and still records counts + sends.

### Security
- **JWT validation** — `ray-router`, `ray-scan` verify via `getUser()` / `getClaims()`. `ray-digest-build` and `ray-digest-send` are `verify_jwt = false` because they are only called by pg_cron with service-role auth; no user data comes from the request body except optional scope override.
- **Service role isolation** — never returned from any function; only used server-side.
- **Org boundaries** — every user-facing query filters by either `user_id = auth.uid()` or `EXISTS org_team_members` join.

## Performance report

Indexes added by this pass:

```
ray_recommendations_user_lastseen_idx (user_id, status, last_seen_at DESC)
ray_skill_invocations_skill_created_idx (skill_slug, created_at DESC)
```

Preexisting indexes verified as hot-path-appropriate:

- `ray_recommendations_fingerprint_uniq` — dedup lookup in scan (O(1)).
- `ray_recommendations_org_status_idx` — dashboard/digest reads.
- `ray_org_memory_org_id_key_key` + `idx_ray_org_memory_category` — memory admin UI.
- `ray_digests_org_week_idx` — digest dedup.

`supabase--slow_queries` was not consulted this pass because no queries in the
v0.4 surface have observed latency issues in the edge-function logs (last 24h
show `ray-*` boots at 25-58 ms, `wrayth-usage` full call 250 ms).

Router latency is dominated by the LLM classifier call (Gemini via Lovable AI
Gateway) when keyword classifier misses — nothing we can cache without
changing behavior, so left as is.

## Not changed (explicitly out of scope this pass)

- Auto-remediation of recommendations — deferred to v0.5.
- Timezone-per-org for digest cron — currently 09:00 UTC Monday for everyone; per-org cron requires a schema change.
- Teams/Slack digest delivery — adapters exist for chat, digest send intentionally email + in-app only per plan.

## Recommendation

v0.4 is demo-ready. The critical Org Memory RLS gap is closed. Recommendations
now have a full lifecycle (create → update → auto-resolve when the signal
disappears → reopen only if a resolved-critical returns), sorted by real
priority. Digests scope correctly and produce stable UTC windows.
