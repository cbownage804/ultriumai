# v0.5 Phase A + B — Security Graph foundation & Incident Timeline UI

Ships the graph foundation and the first consumer (Timeline UI) on top of it.
Everything future (recommendations, memory, incidents, reporting, automation)
should read from the graph rather than maintain its own model.

## What shipped

### Phase A — Security Graph
- `ray_entities` (nodes), `ray_relationships` (edges), `ray_events`
  (append-only timeline). Normalized, org-scoped, RLS-enforced.
- Uniqueness on `(org_id, type, external_id)` for entities, on
  `(source_entity_id, target_entity_id, relationship_type)` for edges, and a
  partial unique on `ray_events.dedup_key` — every projection is idempotent.
- Indexes tuned for the two hot queries: entity-scoped timeline
  (`entity_id, occurred_at desc`) and org-wide recent feed
  (`org_id, occurred_at desc`).
- `ray-graph-sync` edge function (verify_jwt = false, service-role) projects
  `profiles`, `wrayth_devices`, `ray_recommendations`, `ray_org_memory` into
  the graph. Optional one-time `backfill_timeline: true` replays
  `ray_org_timeline` into `ray_events`.
- pg_cron: `ray-graph-sync-hourly` @ minute 17.

### Phase B — Incident Timeline UI
- `/app/timeline` — org-wide feed.
- `/app/timeline/:entityType/:entityId` — entity-scoped focus with a
  "Related" sidebar built from `ray_relationships`.
- Filter bar (search + severity multi-select), day-grouped list, per-event
  "Ask Ray" seeds the floating chat via the existing `ray:panel-send` bus.
- Reads exclusively from `ray_events` + `ray_entities`. No changes to the
  legacy `ray_org_timeline` (kept for the digest builder).

## Security posture
- Entities / relationships / events are all `org_id`-scoped through
  `is_org_team_member` / `is_org_team_admin` / `is_ultrium_employee` — never
  bare `auth.uid()` (per multi-tenant MSP data isolation rule).
- Events are append-only from `authenticated`: no INSERT/UPDATE/DELETE
  policies. Writes go through service-role edge functions.
- `ray-graph-sync` has `verify_jwt = false` because it's cron-driven; it
  performs no user-scoped mutations and only projects from tables that
  already enforce their own RLS.
- Pre-existing warnings from the linter (public buckets, SECURITY DEFINER
  helpers) are documented in the security memory and not introduced by this
  migration.

## Non-goals (deferred to later slices)
- No graph database. Postgres tables only.
- No Relationship Explorer visualization — Phase D.
- No cross-skill reasoning — Phase C.
- No auto-remediation beyond what already exists.
- No conversational polish pass.

## Backfill / operator commands
- One-time timeline backfill (run once after deploy):
  `POST /functions/v1/ray-graph-sync { "backfill_timeline": true }`
- Full org projection: `POST /functions/v1/ray-graph-sync { "since_hours": 720 }`

## Phase C — Cross-skill reasoning (shipped)

`ray-graph-reason` edge function (verify_jwt = false, service-role, cron
every 30 minutes) runs three graph queries and writes results as
`event_type=correlation` events with stable dedup keys:

1. **Device hotspots** — a device with 3+ open danger/warn recommendations
   surfaces as `Hotspot: <device> has N open risks`. Severity escalates to
   `danger` at 5+.
2. **Breach + at-risk device on the same user** — cross-links credential
   exposure with device posture. Severity: `danger`.
3. **Recommendation clusters** — 3+ open recs sharing category + subject →
   "one fix, N risks eliminated" with the rec ids in the payload.

Correlations appear in the timeline like any other event, and clicking the
subject chip focuses the timeline on that entity.

## Phase D — Relationship Explorer (shipped)

`/app/graph` and `/app/graph/:entityId`. Radial `@xyflow/react` layout:
focused entity in the center, direct relationships around it, click any node
to recenter. Node border colored by entity type. Timeline pages with a
focused entity now include an "Explore in graph →" shortcut.

## v0.5 QA / hardening pass

Fixed:
- **RLS gap** — `ray_events` and `ray_relationships` read policies now also
  grant access when the underlying entity is user-owned (`ray_entities.user_id
  = auth.uid()`), matching `ray_entities`. Prior policies would have hidden a
  user's personal device timeline/graph.
- **Search injection surface** — `fetchEvents` search string now strips
  PostgREST `.or()` metacharacters (`,`, `(`, `)`, `.`, `\`, `*`, `%`) and
  caps length at 100 chars before interpolation.
- **Scan latency** — `ray-scan`'s write-through to `ray-graph-sync` is now
  fire-and-forget via `EdgeRuntime.waitUntil` instead of awaiting the
  sub-invocation, so scan responses aren't blocked on graph projection.

Reachability:
- Added `graph` intent + navigation aliases so Ray can jump users to
  `/app/graph` ("open graph", "security graph", "explorer").
- Added an "Open Security Graph →" link on the timeline page header.

Non-issues (verified):
- All new pre-existing linter warnings (public buckets, SECURITY DEFINER
  helpers) are documented in security memory.
- Entity/event upserts leave `first_seen_at` untouched on conflict — only
  `last_seen_at`, `name`, and `attributes` are refreshed, matching intent.
- `ray-graph-reason` dedup keys are per-day, so the same correlation can
  re-emit tomorrow but never twice the same day.
